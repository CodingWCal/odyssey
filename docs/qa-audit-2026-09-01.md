# Odyssey — QA / UI Audit (2026-09-01)

**Scope:** whole app — 17 routes, 63 components, `globals.css` (4,520 lines).
**Method:** automated suites + a static code/CSS pass against the Vercel Web
Interface Guidelines (accessibility, focus, forms, motion, touch, responsive,
theming) using the `web-design-guidelines` skill. **Not a live-browser pass** —
this environment has no `DATABASE_URL`/Clerk creds and blocks external map/POI
APIs, so authenticated pages can't be rendered or screenshotted here (same
constraint and adaptation as the ODY-046 / ODY-108 audits). Items needing a
rendered browser are flagged **[browser]**.

## Findings (prioritized)

### P1 — Keyboard: calendar day cells were not operable — ✅ FIXED (this pass)
`AvailabilityCalendar.tsx` day cells used `onPointerDown`/`onPointerEnter` only,
with no `onClick`/`onKeyDown` — pointer events don't fire for keyboard, so a
keyboard user could focus a day but Enter/Space did nothing (couldn't mark
availability). **Fixed:** added an Enter/Space handler that cycles the focused
day (unset → free → busy) and saves that one cell; dropped the half-implemented
`role="grid"`/`role="gridcell"` (no row structure) for a labelled `role="group"`.
Pointer drag-to-paint unchanged. Gate re-run green.

### P1 — Focus: seamless inline editors have no visible focus state (= ODY-118 F2, still open)
Confirmed real and scoped. `outline: none` with **no** `:focus-visible`
replacement on the borderless inline editors:
- `globals.css:669` (trip-notes title), `:736` `.note-section-title`, `:748` (note-section body), `:792` `.day-notes textarea`, `:818` `.event-notes textarea`, `:2615` (inline field), `:3986` `.trip-search-input input`.
Keyboard users get no focus cue on these. Fix: add a `:focus-visible` treatment
(reuse the `--peri` ring, or an inset background) on each. This is the already-filed
**ODY-118 F2** — the smallest open polish item; recommend taking it next.

### P2 — `autoFocus` on non-modal search inputs
`TripSearch.tsx:88` and `DashboardClient.tsx:146` auto-focus the search field on
mount, which can hijack scroll and pop the mobile keyboard on load. Modal
`autoFocus` (AddEvent/Expense/TripEdit/Wizard) is acceptable. Recommend dropping
`autoFocus` on the two page-level search fields. **[browser]** to confirm feel.

### P3 — shadcn `Button` uses `transition-all`
`ui/button.tsx:7` uses `transition-all` (guideline: animate only
`transform`/`opacity`). Shadcn default; low impact since custom `.od-btn`/token
buttons dominate. Leave unless a jank is observed. **[browser]**

### P3 — Menu dismiss scrim is a `<div onClick>`
`TripCard.tsx:146` closes the "⋯" menu via a click-scrim (`aria-hidden`). Standard
pattern; keyboard closes via the menu's own Escape handling (ODY-118 F3). No action.
